# Данные и восстановление

`Baby` и `CareEvent` — независимые от Core Data значения `Codable`, `Sendable`. `EventKind`, `BreastSide`, `BottleType`, `DiaperType` типизированы. У события есть UUID, UUID ребёнка, даты начала/конца/создания/изменения, данные обеих сторон кормления и заметка.

`Persistence` изолирован `MainActor`; экран читает локальные снимки. Каждое действие валидируется и синхронно сохраняется в контексте до обновления интерфейса. Если сохранение не удалось, контекст откатывается, форма остаётся открытой и показывает ошибку. Сетевой запрос не входит в путь сохранения события. Ошибка запуска CloudKit вызывает одну попытку открыть те же файлы локально без удаления данных. Ошибки самой базы показываются с возможностью повторить открытие.

Граф Core Data: `BabyRecord.events` ↔ `EventRecord.baby`, с обратными необязательными связями. Удаление ребёнка каскадное; такой кнопки в MVP нет. Событие назначается хранилищу родителя, поэтому private/shared-записи не смешиваются через недопустимые межхранилищные связи. Корень совместного доступа — ребёнок со всеми событиями. Unique constraints не используются из-за ограничений CloudKit.

Payload — атомарный JSON-снимок типизированного события. Идентификаторы и даты также сохранены скалярными атрибутами для запросов. Нельзя добавлять обязательные JSON-поля без совместимого декодера: автоматическая миграция Core Data не меняет содержимое JSON.

Хранятся две версии модели. Текущая V2 добавляет необязательный `schemaVersion` с default 1. Автоматическая lightweight migration и persistent history включены. Тест создаёт SQLite по исходной V1, открывает его V2, проверяет профиль, событие, связь и возможность изменения. Старую модель нельзя удалять после выпуска; следующие совместимые изменения добавляются новой версией. Несовместимые изменения потребуют mapping model или отдельной миграции; сброс базы не предусмотрен.

Таймер хранит `start`, `sideStartedAt`, накопленные секунды слева/справа и `end`. Экран лишь вычисляет разность дат. Перезапуск и сворачивание не требуют фонового таймера. Ручное изменение системных часов может изменить вычисленную длительность; отрицательные значения ограничены нулём. Это не медицинский измерительный прибор.

Статистика использует календарные границы суток, включая переходы часового пояса и летнего времени. Сон обрезается по границам выбранных суток и текущему времени, перекрывающиеся интервалы объединяются. Смешанный подгузник увеличивает оба соответствующих счётчика.

В MVP активные таймеры корректируются после завершения; завершённую запись можно редактировать полностью. Независимые таймеры с разных устройств не объединяются автоматически. Ограничения конфликтов и отзыва доступа описаны в [CloudKit.md](CloudKit.md).
