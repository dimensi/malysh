# Live Activities и Dynamic Island

Активные кормления грудью и сон отображаются на экране блокировки и в Dynamic Island. Системный текст таймера вычисляет длительность по сохранённому `CareEvent.start`; приложение не запускает фоновый Timer. Системная типографика и SF Symbols соответствуют приложению; сон использует `Sleep`, кормление — отдельный персиковый `ActivityFeeding`, не меняющий цвета домашних виджетов и основных экранов.

На экране блокировки и в развёрнутом Dynamic Island можно завершить событие, а для кормления — переключить грудь. Expanded Dynamic Island использует системные регионы. Компактное состояние показывает иконку и длительность. Когда система ограничивает ширину Dynamic Island, в том числе на iPhone Duo, видна иконка. Длительность доступна после раскрытия. Минимальное состояние показывает иконку. Кнопки используют `LiveActivityIntent` с `openAppWhenRun = false`. Типы intents входят в обе цели, а исполнение и Core Data остаются в процессе приложения. Live Activity не открывает отдельную базу и не использует App Group для исполнения действий. Обычные [виджеты дневника](Widgets.md) в той же extension читают отдельный снимок App Group.

## Хранение и восстановление

`CareActivityRuntime` предоставляет сцене и intents один `AppStore`, ожидает открытия дневника и слушает уведомления Core Data, CloudKit и изменения общего доступа даже без открытой сцены. Действия перечитывают событие по UUID ребёнка и события. Переключение передаёт целевую сторону, поэтому повторное нажатие из ещё не обновившейся карточки не переключает её дважды. Завершённая или удалённая запись не возобновляется. Ошибки сохранения передаются системе.

После успешного `AppStore.reload()` координатор получает снимок сохранённых событий всех доступных дневников. Выбор другого ребёнка не завершает чужие активные события. Координатор последовательно создаёт отсутствующие активности, обновляет изменённые, удаляет дубли и завершает карточки завершённых, удалённых или недоступных событий. Новые снимки, поступившие во время асинхронного обновления, применяются перед завершением обработки. После intent ожидается окончание согласования с ActivityKit. У завершённого события ActivityKit получает сохранённое время окончания: остров исчезает сразу, а экран блокировки показывает итог не дольше 15 минут после завершения. Удалённое, недоступное или системно истёкшее событие не выдаётся за завершённое.

При повторном запуске используются существующие `Activity.activities`, сопоставленные по UUID событий. Отказ ActivityKit не отменяет сохранение в дневнике; создание повторяется при следующем доступном запуске в foreground. Если работающий процесс получил уведомление о явном смахивании, активность подавляется для того же события; в UserDefaults сохраняются только UUID этого предпочтения отображения. Если после закрытия процесса ActivityKit уже не возвращает сведений об исчезнувшей карточке, при запуске восстанавливается представление сохранённого активного события. Время и состояние события там не хранятся. Схема Core Data, payload `CareEvent` и архитектура CloudKit не изменялись.

Нажатие на саму Live Activity открывает связанную запись по идентификаторам ребёнка и события: активную — на экране «Сегодня», завершённую — в истории. При отсутствии записи или доступа показывается сообщение; обычные маршруты домашних виджетов не меняются.

## Ограничения системы

- Live Activities можно отключить в настройках iOS. Тогда дневник и его таймеры продолжают работать в приложении.
- [Apple ограничивает активность восемью часами](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities). Затем карточка может оставаться на экране блокировки ещё до четырёх часов. При следующем запуске старое представление удаляется перед восстановлением нового для всё ещё активного события. Сохранённое время начала остаётся прежним. Непрерывное отображение ночного сна дольше восьми часов без повторного выполнения приложения система не гарантирует.
- CloudKit доставляет изменения с задержкой. Изменение другим родителем применяется к Live Activity после локального импорта и обработки уведомления либо при возвращении в приложение. Карточка на другом iPhone не является подтверждением мгновенной доставки. Сервер отправки ActivityKit push не добавлялся.
- Смахивание Live Activity скрывает представление, но не завершает событие в дневнике.
- Действия на заблокированном устройстве подчиняются системной аутентификации. Уже завершённая итоговая карточка удаляется по установленному сроку; немедленное удаление при последующем отзыве доступа или удалении записи зависит от поведения ActivityKit.

## Проверки

`CareActivityCoordinatorTests` проверяют восстановление, два параллельных вида событий и разные дневники, обновление начала/стороны/типа/имени, удаление дублей, завершение/удаление/утрату доступа, отказы авторизации и создания, явное скрытие, очистку системно завершённых карточек и смену снимка во время request/update.

`CareActivityActionTests` исполняют настоящие методы intents через внедрённый runtime и Core Data, проверяют накопление длительности по сторонам, повторные действия, недоступные записи, неверные виды событий и восстановление SQLite после повторного открытия. Это локальные проверки, а не доказательство доставки CloudKit между Apple ID.

`LiveActivityUITests` проверяет завершение сна через SpringBoard и сохранение той же записи после перезапуска. Системные кнопки кормления проверяются вручную по матрице, а действия таймера покрыты модульными тестами. Дополнительно проверен запуск действий в новом процессе на пустом симуляторе с обычным хранилищем: кормление, переключение груди и сон сохраняются без открытия интерфейса.

Результаты сборок и проверки системного интерфейса фиксируются в [Validation.md](Validation.md). Для выпуска Widget Extension нужен отдельный provisioning profile: [TestFlight.md](TestFlight.md).
