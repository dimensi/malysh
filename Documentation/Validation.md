## Что проверено

Юнит-тесты покрывают накопление времени каждой груди и идемпотентное завершение, Codable-восстановление активного таймера, сутки с переходом DST, пересечение полуночи, объединение перекрывающегося сна, обрезку текущим временем, подсчёт кормлений/объёма/подгузников и недопустимые значения. Проверены SQLite после повторного открытия, обновление и удаление, связь события с ребёнком в одном хранилище, откат при ошибке кодирования и отсутствии родителя, реальная lightweight migration V1 → V2 без потери записей. Проверены запрет второго локального таймера того же типа, локальное состояние после повторного открытия, запись бутылочки задним числом и возможность повторного открытия базы после ошибки.

UI-тесты выполняют:

1. Быстрая запись мокрого подгузника → завершение процесса → повторный запуск → изменение заметки → сохранение → удаление с подтверждением.
2. Грудное кормление слева → переключение стороны → завершение → начало сна → завершение процесса → восстановление и завершение сна → история и статистика.
3. Бутылочка → изменение объёма до 61 мл → сохранение → статистика; тёмная тема с Dynamic Type accessibility3 и отдельный запуск в светлой теме.
4. Ручная запись сна → история → открытие записи в редакторе.

Скриншоты итогового прогона находятся в `Artifacts/Screenshots`; манифест связывает их с тестами. Выполнена визуальная проверка светлой темы и крупного текста в тёмной теме; при размерах доступности сетка действий становится одноколоночной, а записи и метрики располагаются вертикально.

В первой итерации обнаружено предупреждение о фоновой доставке уведомлений в SwiftUI; доставка переведена на главный RunLoop. Итоговая сводка не содержит runtime warnings. В журналах инструментов Xcode остаются служебные сообщения об отсутствии AppIntents и отладчика; они не являются ошибками приложения. Ошибка открытия каталога в одном юнит-тесте создаётся намеренно для проверки восстановления.

## Границы проверки

CloudKit Sharing реализован настоящими API: два persistent store, private/shared scopes, общий граф ребёнка, системный экран приглашения и управления доступом, сохранение share metadata, приём приглашений при холодном запуске и в открытом приложении. **Полная проверка с двумя Apple ID не выполнена**. На этапе первоначального MVP Developer Team и контейнер не настраивались; дальнейшая настройка устройства и Production-схемы описана ниже. Приглашения, доставка изменений, конфликты и отзыв доступа пока не подтверждены. Точные действия и сценарии — [CloudKit.md](CloudKit.md).

Сетевой путь отключён в локальных тестах; они подтверждают работу локальной базы без обращения к CloudKit. Авиарежим на физическом устройстве, фоновые лимиты iOS, аппаратные жесты и VoiceOver на устройстве не проверялись. Минимальная версия компиляции — iOS 17; runtime iOS 17 отдельно не запускался. Поддерживается iPhone; интерфейс iPad не заявляется. Проверка доступности включает подписи и крупный текст, но не является полным аудитом WCAG или VoiceOver.

Первоначальная сборка для arm64-симулятора сохранена локально. Новые ZIP-архивы не создаются. Для физического устройства используются подпись в Xcode и TestFlight.

## Дополнение: CloudKit на физическом iPhone и экспортное шифрование

4 ноября 2026 после запуска пользователем на устройстве обнаружено отсутствие `com.apple.developer.icloud-container-environment` в подписи Debug-сборки. Исправлено: Debug явно использует Development, Release — Production. Идентификатор контейнера совпадает в коде, подписи и provisioning profile. Выбранная пользователем Team сохранена в текущем проекте и Project.swift. Проект Xcode не перегенерировался поверх пользовательских правок; Tuist проверен в изолированной копии.

Подписанные Debug- и Release-сборки для физического iPhone прошли успешно. В подписи Debug подтверждено Development, Release — Production. Обновление Debug установлено поверх существующей версии без удаления контейнера данных. После разблокировки устройства приложение успешно запущено. Пользователь подтвердил статус «iCloud готов / Последняя синхронизация». Это подтверждает подключение на одном iPhone; обмен между двумя Apple ID и полный сценарий приглашения по-прежнему отдельно не подтверждены. CloudKit Console автоматически не проверена: страница браузера потребовала обработки пользователем.

Добавлена обработка вложенных/частичных ошибок CloudKit короткими русскими сообщениями без технических идентификаторов. Кнопка приглашения требует успешного setup обоих хранилищ и доступной учётной записи. Добавлены четыре теста ошибок и готовности. Итоговый повторный прогон: **24/24 прошли (20 unit + 4 UI), 0 ошибок, 0 пропусков, 0 runtime warnings**. Результат — `Artifacts/CloudKitFix/Tests-verified.xcresult`, сводка — `Artifacts/CloudKitFix/test-summary.json`. SwiftLint: 0 нарушений, SwiftFormat: 0 файлов требуют форматирования.

Для текущего кода, использующего только шифрование Apple OS/iCloud без своей криптобиблиотеки, добавлен Boolean `ITSAppUsesNonExemptEncryption = false` в Project.swift и действующий Info.plist. Ключ проверен в **собранной Release `.app`**. Новая декларация применяется при следующей загрузке бинарника. Для уже загруженной версии в форме Apple подходит «None of the algorithms mentioned above»: перечисленные там варианты относятся к алгоритмам приложения сверх системного шифрования.

Основание: [документация Apple по шифрованию и экспортной декларации](https://developer.apple.com/help/app-store-connect/reference/app-information/export-compliance-documentation-for-encryption) и [настройке декларации для TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/provide-export-compliance-information-for-beta-builds).
