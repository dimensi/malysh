# TestFlight по тегу версии

Workflow `.github/workflows/testflight.yml` предназначен для репозитория `dimensi/malysh`. Обычный выпуск запускается при отправке тега вида `vX.Y.Z`, например `v1.2.3`. Существующий тег можно запустить вручную через workflow из ветки `main`. Перед установкой материалов подписи workflow проверяет формат тега, совпадение выбранного коммита с тегом и наличие коммита в истории `origin/main`. Обычный push ветки не запускает загрузку.

## Настройка GitHub Secrets

Добавьте секреты в Settings → Secrets and variables → Actions:

| Секрет | Содержимое |
| --- | --- |
| `IOS_DISTRIBUTION_P12_BASE64` | Base64 сертификата Apple Distribution вместе с закрытым ключом в `.p12` |
| `IOS_DISTRIBUTION_P12_PASSWORD` | Пароль экспорта `.p12` |
| `IOS_PROVISIONING_PROFILE_BASE64` | Base64 профиля распространения App Store Connect для `dev.dimensi.malysh` |
| `IOS_WIDGET_PROVISIONING_PROFILE_BASE64` | Base64 отдельного профиля App Store Connect для `dev.dimensi.malysh.widgets` (обязателен) |
| `ASC_PRIVATE_KEY_BASE64` | Base64 закрытого ключа App Store Connect API (`.p8`) |
| `ASC_KEY_ID` | Идентификатор API-ключа |
| `ASC_ISSUER_ID` | Issuer ID команды App Store Connect |

Сертификат, профиль и API-ключ должны относиться к команде `YBBAN7R28K`. Профиль должен разрешать нужные возможности приложения, включая CloudKit в Production. У API-ключа должны быть права на чтение сборок и загрузку приложения. Закрытые ключи и пароли нельзя добавлять в репозиторий, issue, отчёты или журналы.

Для CI созданы ручные профили `Malysh GitHub Actions App Store App Group` и `Malysh Widgets GitHub Actions App Store App Group` с одним уже существующим сертификатом Apple Distribution. Профили, автоматически управляемые Xcode, для ручной подписи CI не используются. Текущий сертификат и оба профиля действуют до **4 декабря 2026**: до этой даты обновите сертификат/профили и соответствующие секреты GitHub, чтобы следующие выпуски продолжали подписываться.

Скрипт `Scripts/ci-signing.sh setup` устанавливает материалы во временные файлы и отдельную связку ключей. Он передаёт следующим шагам через `GITHUB_ENV` значения `PROFILE_UUID`, `PROFILE_NAME`, `WIDGET_PROFILE_UUID`, `CI_KEYCHAIN_PATH`, `CI_KEYCHAIN_PASSWORD` и `ASC_KEY_PATH`; пароль связки должен быть замаскирован в журнале. Подкоманда `cleanup` выполняется даже после ошибки и должна безопасно работать, если установка не началась или завершилась частично. Профили и сертификаты имеют срок действия: обновляйте секреты до истечения или после отзыва. При отзыве API-ключа замените также его ID и закрытый ключ.

## Расширение и App Group

Explicit App ID `dev.dimensi.malysh.widgets` и App Group `group.dev.dimensi.malysh` зарегистрированы в команде `YBBAN7R28K`. Группа назначена обоим App ID: `dev.dimensi.malysh` и `dev.dimensi.malysh.widgets`. Оба distribution-профиля и их GitHub Secrets обновлены под эту группу и проверены выпуском 1.1.6. У расширения нет CloudKit или Push Notifications; у приложения эти возможности сохранены. При следующих изменениях capabilities пересоздавайте нужные профили и обновляйте соответствующие секреты. Изменения кода сами не создают App ID, группу, профиль или секрет.

Скрипт проверяет оба профиля, устанавливает их без перезаписи существующих файлов и при очистке удаляет только принадлежащие этому запуску файлы. Fastlane передаёт `MALYSH_PROFILE_UUID` и `MALYSH_WIDGET_PROFILE_UUID`; каждая цель использует свой `PROVISIONING_PROFILE_SPECIFIER`. Экспорт IPA содержит соответствие обоих bundle ID своим профилям.

## Выпуск

После слияния нужных изменений в `main` создайте и отправьте тег:

```sh
git switch main
git pull --ff-only
git tag v1.2.3
git push origin v1.2.3
```

Для ручного повтора сначала проверьте в App Store Connect, что предыдущий запуск не загрузил сборку, в том числе ожидающую обработки. Запускайте существующий тег без его перемещения или пересоздания:

```sh
gh workflow run testflight.yml --ref main -f release_tag=v1.2.3
```

Workflow использует Apple Silicon runner `xcode-27`, Xcode 27.2 и Ruby 4.0. Toolchain сверена с [описанием образа arm64](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md). Fastlane закреплён на `2.241.2` в `Gemfile`. Workflow выбирает доступный iPhone Simulator с самой ранней установленной версией iOS не ниже 27.0 и ждёт его готовности в отдельном шаге с лимитом 10 минут. Журнал загрузки сохраняется в `Artifacts/simulator-boot.log`, список доступных устройств — в `Artifacts/simulators.json`. Подпись и загрузка требуют успешного полного набора unit- и UI-тестов. CI использует сохранённый в репозитории `Malysh.xcworkspace` без запуска Tuist.

Pull request в `main`, меняющий этот workflow, `Scripts/simulator-id.py`, `Gemfile`, `Gemfile.lock` или `fastlane/**`, проверяет установку закреплённых Ruby-зависимостей, загрузку Fastlane-конфигурации и запускает тот же полный набор тестов на hosted runner. Проверка тега, подпись и публикация в таком запуске пропускаются; секреты подписи не используются. Проверки PR имеют отдельную группу concurrency и не задерживают выпуск. Изменения инфраструктуры можно проверить до слияния без повторной публикации уже выпущенной версии.

Версия приложения берётся из тега без `v`. Номер сборки — последний номер TestFlight для этой версии плюс один; при отсутствии сборок используется `1`. Это учитывает ранее загруженные вручную сборки. Существующий номер должен быть целым числом. Запуски TestFlight выполняются последовательно, без отмены предыдущего. Не загружайте вручную другую сборку той же версии одновременно с CI; перед повторным запуском после успешной загрузки дождитесь появления предыдущей сборки в App Store Connect.

Подпись ручная, среда CloudKit — Production. Загрузка не отправляет сборку на внешнее тестирование и не меняет состав тестировщиков. Для существующей внутренней группы `parents` включён `hasAccessToAllBuilds`: после обработки Apple новые сборки доступны участникам автоматически. Workflow не ждёт завершения обработки Apple: зелёный шаг загрузки ещё не означает, что сборка уже доступна в TestFlight. Проверьте обработку, доступность в группе и предупреждения в App Store Connect.

## Результаты и ограничения

GitHub хранит результаты тестов, журнал загрузки симулятора и журналы сборки в течение семи дней. IPA, архив Xcode и материалы подписи не публикуются как артефакты. Workflow не создаёт исходный ZIP-архив; автоматически предоставляемые GitHub ссылки на исходники тега не являются действием этого workflow.
