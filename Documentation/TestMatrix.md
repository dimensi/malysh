# Матрица тестов

Для небольшого дневника нужен компактный набор, защищающий основные действия и данные. Не тестируем каждую функцию, ветку реализации, подпись или вариант оформления. На `main` с фотографиями и интерактивными виджетами набор был сокращён со **168 до 65 методов: 52 unit/integration + 13 UI**. Разобраны и старые сценарии, и проверки обеих новых функций; отдельный render target удалён. Вкладка «Малыш» добавляет семь методов для первоначального ввода, миграции V4 → V5, атомарного сохранения и навигации. Необязательное время рождения добавляет два сценария: сохранение локального времени при смене часового пояса и добавление с последующим удалением через редактор. Текущий набор — **84 метода (66 unit/integration + 18 UI)**.

Перед новым тестом найдите строку матрицы и назовите конкретный пользовательский сбой. По умолчанию исправьте или замените существующий сценарий. Увеличение набора требует нового существенного риска либо воспроизводимой регрессии, которую он пока не ловит. Не переносите удалённые проверки в мегатесты или огромные таблицы ради красивого счётчика. Косметические правки проверяются вручную.

## Запуск

`Scripts/check.sh` проверяет форматирование/lint, генерирует проект и передаёт дополнительные аргументы в `xcodebuild`. В обычной задаче выбирайте затронутую строку:

```sh
rtk proxy env RESULT_BUNDLE_PATH=Artifacts/DomainChecks.xcresult bash Scripts/check.sh \
  -only-testing:MalyshTests/DomainTests

rtk proxy env RESULT_BUNDLE_PATH=Artifacts/ActivityChecks.xcresult bash Scripts/check.sh \
  -only-testing:MalyshTests/CareActivityCoordinatorTests \
  -only-testing:MalyshTests/CareActivityActionTests \
  -only-testing:MalyshUITests/LiveActivityUITests
```

Для строки S изменение установки виджета проверяйте на чистом Home без уже установленного виджета. Быстрый путь с существующим виджетом не подтверждает работу системного каталога.

Для выпуска полный набор выполняется один раз в релизном CI до подписи и загрузки, без обязательного локального повтора. После общей перестройки тестов полный набор также нужен в CI. При необходимости ручной локальный запуск:

```sh
rtk proxy env RESULT_BUNDLE_PATH=Artifacts/FullCheck.xcresult bash Scripts/check.sh
```

Для изменений скриптов выпуска или схемы:

```sh
rtk proxy python3 -m unittest discover -s Scripts/tests -v
```

Для повторного запуска задайте новый `RESULT_BUNDLE_PATH`; устройство можно выбрать через `DESTINATION`. После успешного полного прогона повторять его без изменений не нужно. При сбое сначала разберите и повторите только упавший сценарий. Повторный успех не скрывает первую ошибку. CI TestFlight сохраняет полный прогон приложения; schema workflow запускает свои Python-проверки.

У фотографий убраны отдельные roundtrip-модели, проверка тестового JPEG-helper, повторные проходы пустой галереи/выбора источника/закрепления, дубли workflow-ошибок в UI и визуальный smoke. У виджетов убраны повтор установки, дополнительный cold breast сценарий, повтор rollback через недопустимую дату и несколько вариантов anchors.
